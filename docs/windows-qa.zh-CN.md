# FileBoundary — Windows 实机验收指南（开发预览）

**重要：FileBoundary 目前不是可独立解密 E-SafeNet 的工具。** 这次测试验证 Windows 程序能运行、可以只读识别加密文件，并比较**另行通过正式授权流程导出的文件**。目前无法凭密文直接生成明文。

## 下载与启动

1. 用有权访问 `turinglambdaai/fileboundary` 私有仓库的账号登录 GitHub。
2. 打开 [Windows GUI 构建工作流](https://github.com/turinglambdaai/fileboundary/actions/workflows/windows-gui.yml)。
3. 选择最新的 **main 分支且结果为绿色 Success** 的运行，在页面底部 **Artifacts** 下载 `FileBoundary-Windows-x64-dev`。功能分支产物只用于 PR 审查。
4. 将 ZIP **全部解压**到本地文件夹，例如 `D:\Tools\FileBoundary`。必须保留 `runtime/`、`res/`、DLL 和 `RivetHost.exe` 的完整目录结构，不要在压缩包内直接双击。
5. 运行 `RivetHost.exe`。这是尚未签名的便携**开发预览版**，并非已完成的安装包。如果受到系统或公司策略阻止，请记录实际错误和程序来源；**不要关闭 Windows 安全软件或企业防护**。

## 三项不修改原件的测试

1. **加密文件扫描**：第一个输入框填入被加密的测试文件完整路径，点击 **Scan / 扫描**。如果当前进程读取到已知 E-SafeNet 封装，应显示 `Known encryption-wrapper signatures: 1`。如果显示 0，可能是透明解密提供了不同的进程读取视图，也可能是未识别的封装格式，需要继续分析，不可直接断定文件未加密。
2. **系统诊断**：点击 **Diagnostics / 诊断**。观察过滤驱动和实例枚举状态。权限不足不等于系统没有过滤驱动。只有获得本地策略许可时才使用管理员权限，不修改驱动。
3. **授权导出验证**：第一个输入框为原始加密文件路径，第二个框填写**已经通过官方认可的解密/导出方式取得的候选文件**，点击 **Check Export / 验证导出**。
   - `FAILED`：候选文件仍检测到 E-SafeNet 加密封装，或在 CLI 场景下可信明文基线不匹配。
   - `UNVERIFIED`：暂未检测到明确拒绝条件，**不是已经成功解密**。
   - GUI 不会生成明文、不修改文件，也不会绕过加密软件的访问控制。

## 受控对照测试

仓库根据 ADR-0004 已有同一内容的加密/明文 DOCX 对照样本。CI 会检测封装和哈希，也会确认对照结果不会被自动判为“已解密”。真实电脑上的验收请只使用获授权的测试副本，不要再把个人密文或明文上传到仓库。

## 请保留这些验收信息

- Windows 版本与启动是否成功，失败时的完整错误代码
- 界面及嵌入的 Racket 是否正常加载、按钮是否可点击
- 扫描结果中的计数与文件封装分类（**删除个人路径**）
- 过滤驱动诊断状态（按需脱敏主机名或服务名）
- 是否存在授权导出的候选文件：**有/无**；比较结果是 `FAILED` 还是 `UNVERIFIED`
- 导出文件能否被普通 PDF/Office 阅读器独立打开：**能/不能/未测试**
- 崩溃、缺少 DLL、运行库等信息（隐藏真实文件名和路径）

**任何情况下都不要因 FileBoundary 的输出删除原始密文。** 如果没有授权明文导出渠道，核心恢复目标仍处于阻塞状态，而不是安装测试通过即视为成功。
